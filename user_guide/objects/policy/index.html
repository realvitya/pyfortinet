Policies and packages#

The policy module models policy packages (PPs) and the policies within them. Use an explicit ADOM and the connection conventions in the object guide.

PolicyPackage#

Read packages in the selected scope, or select an existing package by name:

from pyfortinet.fmg_api.policy import PolicyPackage

packages = fmg.get(PolicyPackage).data
package = fmg.get(PolicyPackage(name="branch-policy")).first()
for item in packages:
    print(item.name, item.type)

The model's name field identifies a package; scope_member describes its assigned devices and VDOMs. Both scope_member and the API spelling "scope member" are accepted as input; API payloads use "scope member". An omitted member list remains absent, while [] is sent explicitly. Folder responses contain nested PolicyPackage instances in subobj.

Manage scope members#

Packages returned by fmg.get are bound to their connection and ADOM. Use their member methods to change assignments without writing the other package settings:

from pyfortinet.fmg_api.common import Scope

package = fmg.get(PolicyPackage(name="branch-policy")).first()
members = [Scope(name="branch-fw", vdom="root")]
package.add_scope_members(members)
package.delete_scope_members(members)
package.set_scope_members(members)
package.update_scope_members(members)
package.unset_scope_members()
package.refresh()

These calls demonstrate separate operations: ADD adds members, DELETE removes the supplied members, SET replaces the member list, UPDATE sends a member-table update, and UNSET clears all assignments. Each call returns an operation response. Check its success value when raise_on_error is disabled. The local scope_member list is reloaded only by refresh(). Member dictionaries such as {"name": "branch-fw", "vdom": "root"} are also accepted.

With AsyncFMG, await each call, including get and refresh:

package = (await fmg.get(PolicyPackage(name="branch-policy"))).first()
await package.add_scope_members([Scope(name="branch-fw", vdom="root")])
await package.refresh()

For a locally constructed package, pass fmg=fmg and optionally fmg_scope="my-adom". The member methods require a package name; use its full path (for example, name="folder/branch-policy") when it is inside a folder. The connection's selected ADOM is used unless the package already has a scope. Global scope is also supported.

PackageSettings#

PackageSettings is embedded in a policy package, not added independently. Its ssl_ssh_profile field is a list of profile names, serialized as "ssl-ssh-profile"; a single string is also accepted and converted to a one-item list. This example creates a new package assigned to an existing device and VDOM:

from pyfortinet.fmg_api.common import Scope
from pyfortinet.fmg_api.policy import PackageSettings, PolicyPackage

package = PolicyPackage(
    name="example-branch-policy",
    scope_member=[Scope(name="branch-fw", vdom="root")],
    package_settings=PackageSettings(fwpolicy_implicit_log="enable"),
)
fmg.add(package)

The package name must be unused. Assigning a package and creating its database record do not install it onto the device. InstallDeviceTask is for device settings; this library currently has no dedicated high-level policy-package installation task.

Policy#

Supply pkg to locate the package and policyid when selecting an individual policy. The connection supplies the ADOM unless the model has an explicit adom.

from pyfortinet.fmg_api.policy import Policy

policies = fmg.get(Policy(pkg="branch-policy")).data
policy = fmg.get(Policy(pkg="branch-policy", policyid=10)).first()
for item in policies:
    print(item.policyid, item.name, item.action)

To update one field on an existing policy:

fmg.update(Policy(pkg="branch-policy", policyid=10, comments="Reviewed branch rule"))

pkg and adom locate the resource and are excluded from the configuration payload. Address and service references accept names or supported named firewall models. Supplying a referenced model does not create it.

Policy profile references, including diameter_filter_profile, av_profile, ips_sensor, application_list, and profile_group, are lists of profile names, matching the FMG schema. Single strings are accepted and normalized to one-item lists. None omits a profile field from write payloads; an explicit [] is sent as an empty array. profile_type remains the "single" / "group" selector.

rule = Policy(pkg="branch-policy", policyid=10, diameter_filter_profile=["example-diameter"])
assert rule.model_dump(by_alias=True, exclude_none=True)["diameter-filter-profile"] == ["example-diameter"]

The following constructs a local rule for inspection. It does not write the rule:

from pyfortinet.fmg_api.firewall import Address, ServiceCustom

rule = Policy(
    pkg="branch-policy",
    name="Example application access",
    srcintf=["lan"],
    dstintf=["wan"],
    srcaddr=[Address(name="example-network")],
    dstaddr=["all"],
    service=[ServiceCustom(name="example-web")],
    action="accept",
    schedule=["always"],
    logtraffic="all",
)
payload = rule.model_dump(by_alias=True, exclude_none=True)
assert payload["srcaddr"] == ["example-network"]
assert payload["service"] == ["example-web"]
assert "pkg" not in payload

Before adding a rule, confirm that the package, interfaces, addresses, services, and schedule exist, and review the intended policy placement. This example does not claim automatic ordering or package installation.
